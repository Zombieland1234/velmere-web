## What was verified

The repository uses ESLint flat config from `eslint.config.mjs`. The canonical lint command was previously `eslint .`. C13 also ran `eslint . --max-warnings 0`; that strict warning gate failed because warnings remain, but this P06 area is specifically about **errors and scan coverage**, not warning cleanup.

The active-source inventory is based on `git ls-files`, not on directory assumptions. Every tracked file with one of these code extensions is considered active ESLint source unless it is the single justified generated tracked file:

`.js`, `.jsx`, `.mjs`, `.cjs`, `.ts`, `.tsx`, `.mts`, `.cts`.

Intentional tracked generated exclusion:

- `next-env.d.ts` — generated by Next.js and already globally ignored.

All other tracked JS/TS-family files must appear in the actual `ESLint.lintFiles(["."])` traversal. This means a future tracked source file placed under a globally ignored directory such as `archive/`, `artifacts/` or `.generated/` becomes a hard coverage failure instead of being silently accepted.

## Changes

### 1. Coverage guard

Added:

`scripts/c14/check-eslint-coverage.mjs`

The guard:

1. inventories tracked files with `git ls-files`;
2. derives the complete tracked JS/TS-family source set;
3. removes only the explicit generated tracked exception `next-env.d.ts`;
4. asks ESLint for the real `eslint .` traversal using its Node API;
5. compares expected active paths to actual linted paths;
6. fails if even one tracked active source file is missing;
7. reports exact error/warning totals and per-subsystem counts.

### 2. Package scripts

Updated lint entry points so ordinary and strict lint both execute the coverage guard first:

- `lint`: coverage guard + `eslint .`
- `lint:coverage`: dedicated coverage verifier
- `lint:direct`: coverage guard + existing `eslint . --max-warnings 0`

The strict warning policy is unchanged; P07 owns the remaining warning cleanup.

### 3. CI prevention control

Added:

`.github/workflows/c14-p06-eslint-scope.yml`

It runs on this P06 branch and on pull requests to `main` affecting JS/TS/config/lockfile/lint-workflow inputs.

The workflow uses the exact lockfile installation and Node `24.18.0`, then runs the guarded lint.

It also contains a negative control: CI temporarily stages `archive/c14-p06-hidden-fixture.ts`. Because `archive/**` is globally ignored, the guard must reject that tracked source as missing from traversal. The workflow then removes the fixture and requires a clean working tree before the real lint.
