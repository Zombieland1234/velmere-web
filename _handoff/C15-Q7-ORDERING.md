# C15-Q7: isolated ordering persistence and strict receipt contract

Base is the local C15-Q6 content tree `8e455d08a084a652e1125e2073706278c4eed719`, descended from remote Q5 `57a29cfccb9b5e3718ae89c8426e7155a0c086ee`. This is a local candidate, not a new remote commit, deployment, independent audit or release approval. NO_GO remains.

The existing six-kind priority policy in `stripe-webhook-state.ts` is unchanged. Q7 adds an isolated SQL implementation of the previously registered watermark RPC and a strict application receipt parser. SQL stores event identity separately from the current per-subject watermark; the response binds the request, previous state, decision and actual current state. Identity conflicts, malformed booleans, unknown reasons and inconsistent decisions refuse rather than infer success. Development memory uses the same identity constraint. Functions remain SECURITY INVOKER with pinned search_path and forced RLS; service_role is a trusted backend. SQL installation requires a disposable-test acknowledgment and refuses existing objects. This is not an applied production migration.

The application and new versioned RPC response must be rolled out together. SQL preserves priority-over-time behavior and same-priority same-second rejection; no address, known corpus label, price or new sales policy has been introduced. Ordering is admission state, not a receipt that an effect finished. A duplicate watermark can be resumed by an inbox retry; an already running handler is not stopped by later admission. Leases/watermarks do not imply globally exactly-once callbacks. Holds, reconciliation, multi-account/Stripe Connect scoping, real authentication, networked PostgREST and Stripe TEST checkout remain separate open work.

The Q7 test scope adds 29 parser, 47 SQL and eight joined-handler cases to the 816 existing cases: 900 planned registered cases. SQL tests execute PGlite, not native concurrent PostgreSQL. The 36 kind-pair tests each examine three time relations; these 108 policy combinations are not 108 extra tests. Joined tests use real ingress/SDK HMAC/dispatcher/Supabase client plus Q4/Q5/Q6/Q7 SQL, with controlled transports and fixture grants. No actual payments or customer data are involved. Actual final pass/fail results belong to timestamped evidence, not this source note.

Failure history includes a PostgreSQL regex repetition-limit error in the first new SQL, fixed with explicit length/character checks; the original 76-test failed log is retained. Initial full strict uncovered two old C8 test fixtures with invented reason strings; fixtures now build real policy states, without changing their assertions. The initial new-test prefer-const lint error was fixed without changing rules. No previous log is overwritten. Engine, UI, CSS, public assets, auth and dependency lockfile are not changed by Q7.
